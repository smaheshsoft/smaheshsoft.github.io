Architecture Notes — Service Communication

REST or gRPC
for microservices?

Same call, two contracts — one readable on the wire, one compiled from a schema. Same GetCustomer, both ways, and how I choose.

01

REST

JSON · HTTP/1.1 · human readable
CustomerController.cs
[HttpGet("{id}")]
public async Task<Customer> GetCustomer(int id)
{
    return await _service.GetCustomer(id);
}
Response
{
  "id": 101,
  "name": "Mahesh",
  "city": "Bangalore"
}
Simple, readable, easy to test. Any browser or curl can call it — no contract tooling, no codegen.
02

gRPC

Protocol Buffers · HTTP/2 · compact binary
customer.proto
service CustomerService {
  rpc GetCustomer (CustomerRequest)
      returns (CustomerResponse);
}
CustomerServiceImpl.cs
public override async Task<CustomerResponse> GetCustomer(
    CustomerRequest request, ServerCallContext context)
{
    var c = await _service.GetCustomer(request.Id);
    return new CustomerResponse
    { Id = c.Id, Name = c.Name, City = c.City };
}
Contract first, clients generated from it. Messages travel as compact binary, not JSON text.

Performance

The path a single request takes
RESTClientHTTPJSONService
gRPCClientHTTP/2ProtobufService

gRPC generally gives

Lower latency
Smaller payloads
Faster serialization
Better streaming support

But the gain depends on

Payload size · Number of requests
Network latency
Serialization overhead
Hardware · Implementation

So I don't say

“gRPC is always 10x faster.”
I say: benchmark your actual workload.

Rule of thumb

What the requirement is really asking for
Web / mobile APIREST
Microservice → microservicegRPC
Public APIREST
Low latencygRPC
Easy debuggingREST
High throughputgRPC
Asynchronous communicationKAFKA / EVENT HUB / SERVICE BUS
StreaminggRPC

My preferred architecture

Not one protocol everywhere — one per hop
FrontendRESTAPI GatewayReach and simplicity at the edge, where clients are diverse and debuggability matters most.
MicroservicegRPCMicroserviceTyped contracts and low latency on the calls you make thousands of times a minute.
MicroserviceEVENT BUSMicroserviceWhen the caller shouldn't wait for an answer at all — Kafka, Event Hub or Service Bus.
REST at the edge. gRPC inside. Events when nobody's waiting.
